# 3단계 진행 상황 (2026-10-29)

## 3-1. 의존성과 빌드: 완료

- 쓰지 않는 `com.google.ai.client.generativeai:0.9.0`, `guava:31.1-android` 제거 (코드에서 쓰는 곳 없음). 빌드, 단위 테스트 164개, 에뮬레이터에서 앱 실행과 주사위 확인
- gson 선언을 실제로 쓰는 2.14.0으로 맞춤. `GsonRegressionTest`(세이브 저장/불러오기, type 없는 예전 세이브 복구, AI 이벤트 JSON) 통과
- 출시 빌드만 `abiFilters 'arm64-v8a'`. 출시 APK에는 `lib/arm64-v8a`만, 디버그 APK에는 `arm64-v8a`와 `x86_64`
- **출시 빌드가 원래 실패하고 있었다**: PNG 확장자인데 실제로는 JPEG인 이미지 12개(`job_*` 9개, `item_img_35~37`)를 출시 빌드의 PNG 압축이 처리하지 못함. 확장자를 `.jpg`로 바꿨다 (리소스 이름은 같아서 코드 변경 없음)

## 3-2. 모델 배포: 완료 (첫 실행 다운로드)

계획서의 Play Asset Delivery 대신 첫 실행 때 받는다 (0-A 결정: 모델 2.58GB가 에셋 팩 한도 1.5GB를 넘음).
받는 곳은 사용자가 Hugging Face 주소로 정했다 (2026-10-29). 받는 시점과 네트워크는 추천안대로 했다.

| 항목 | 정한 것 |
| --- | --- |
| 받는 곳 | `https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/resolve/1caa527c1e88b55f046fcd8d2b4265606680663d/gemma-4-E2B-it.litertlm`. 리비전을 고정해서 저장소가 바뀌어도 측정한 파일을 받는다. 로그인 필요 없음, 이어 받기(Range) 지원 |
| 확인 | 크기 2,588,147,712바이트와 SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c` (0-A, 2단계 측정에 쓴 PC의 파일과 같음) |
| 언제 | 메인 화면에 올 때마다 확인하고, 없으면 받기 시작한다. 게임은 바로 하고, 받는 동안 주사위는 클라우드 |
| 네트워크 | 데이터 요금 없는 네트워크(보통 Wi-Fi)에서만, 로밍 안 함 |
| 저장 위치 | `getExternalFilesDir(null)/models/` (개발용 adb push와 같은 자리). 받는 동안은 `.download` 임시 이름이고, 확인을 통과해야 모델 이름으로 바꾼다 |
| 받는 기기 | 로드 조건(arm64, 디버그는 x86_64도 / 램 기준)을 통과한 기기만. 받은 뒤에도 1GB가 남아야 시작한다 (모두 3.7GB) |
| 실패 | 받기 실패나 해시 불일치가 3번 쌓이면 더 받지 않는다. 실패 뒤 다시 받기는 앱 프로세스마다 한 번 |
| 백업 | 자동 백업과 기기 이전에서 `models/`를 뺐다. 백업 한도(25MB)를 넘으면 세이브까지 백업되지 않기 때문 |

구현은 `ModelDownloader`. 시스템 DownloadManager를 써서 앱이 꺼져 있어도 받고, 연결이 끊기면 이어 받고, 알림에 진행이 보인다.
앱이 살아 있을 때 다 받으면 바로 확인하고, 꺼져 있을 때 끝났으면 다음에 메인 화면에 올 때 확인한다.
게임 중에 받기가 끝나면 그 자리에서 모델을 올린다 (`OnDeviceBackend`가 "모델 파일 없음"으로 `UNAVAILABLE`이었으면 `warmUp` 때 다시 본다).

### 에뮬레이터 확인 (`TextDungeon_LLM`, CPU)

| 상황 | 결과 |
| --- | --- |
| 모델이 이미 있음 (adb push) | 받지 않음. 설정 "온디바이스 AI: 준비됨" |
| Wi-Fi 끄고 앱 실행 (모바일 데이터만) | 받기 대기 (JobScheduler가 `NOT_METERED` 네트워크를 기다림). 설정 "받는 중 (Wi-Fi 연결 대기)" |
| 게임 중(이어하기)에 Wi-Fi 켬 | 6분 41초 만에 받음 (에뮬레이터 네트워크 SSL 오류로 3번 끊겼다 이어 받음). 해시 확인 2.7초, 바로 CPU 초기화 2.8초, 다음 주사위는 `OnDevice(CPU)`가 4.2초에 응답 |
| 받는 중에 앱 프로세스를 죽임 (`am kill`) | DownloadManager가 계속 받아 6분 9초에 끝남 (SSL 오류로 1번 끊겼다 이어 받음). 다음에 앱을 열자 해시 확인 2.9초 뒤 모델 이름으로 바꿈. 확인하는 동안 설정 "받는 중 (파일 확인)", 끝나고 "준비됨" |

PC에서 같은 주소로 받으면 초당 약 37MB라 2.6GB에 1분 남짓이다. 에뮬레이터는 그보다 훨씬 느렸다.

계획서 3단계 완료 기준의 "bundletool 로컬 테스트로 설치 → 팩에서 모델을 찾아 온디바이스로 동작"은 "첫 실행 때 받은 모델로 온디바이스 동작"으로 바뀌었고, 위 표로 확인했다.

## 3-3. 상태 표시: 완료

설정 화면의 글자 크기 아래에 한 줄. 화면이 떠 있는 동안 1초마다 새로 고친다.

| 표시 | 언제 |
| --- | --- |
| 준비됨 | 모델 파일이 있음 (아직 올라가기 전이라도) |
| 받는 중 N% / 받는 중 (Wi-Fi 연결 대기) / 받는 중 (파일 확인) | 받는 중, Wi-Fi 기다림, 다 받고 해시 확인 중 |
| 사용 불가 (지원하지 않는 기기 / 저장 공간 3.7GB 필요 / 받기 실패 / 이 기기에서 실행 실패) | 받지 않거나 못 받음, 받았지만 GPU 초기화나 추론이 실패해 `FAILED` |

- 모바일 데이터에서는 DownloadManager 상태가 `PAUSED`가 아니라 `PENDING`으로 남는다 (에뮬레이터 API 36). 그래서 지금 네트워크가 데이터 요금 없는 네트워크인지 직접 보고 "Wi-Fi 연결 대기"를 띄운다 (`ACCESS_NETWORK_STATE` 권한 추가)
- 응답한 백엔드 로그는 1단계에서 넣었다
- 단위 테스트: `OnDeviceStatusLineTest`(표시 문구 4개), `ModelDownloaderTest`(크기·해시 확인, 고정 리비전 6개). 전체 174개 통과

오픈소스 라이선스 창도 고쳤다. 3-1에서 뺀 Guava, Generative AI SDK를 지우고 OkHttp, LiteRT-LM, Gemma 4 E2B 모델을 넣었다.

### 모델 받기 스위치 (사용자 요청 추가)

상태 줄 위에 "혼돈의 주사위 AI 모델 받기 (Wi-Fi, 2.6GB)" 스위치. 기본은 켬.

- 끄면: 모델을 내리고, 받던 것을 취소하고, 받아 둔 모델과 엔진 캐시를 지운다. 받아 둔 모델이 있으면 먼저 확인 창("AI 모델 지우기")을 띄우고, 취소하면 스위치가 다시 켜진다. 상태 줄은 "꺼짐 (주사위는 클라우드)"
- 켜면: 이전 실패 횟수를 지우고 바로 받기 시작
- 모델을 못 쓰는 기기(ABI, 램)에서는 스위치를 막는다

엔진 캐시: 모델 이름으로 시작하는 파일을 `cacheDir`에 만든다. 에뮬레이터에서 GPU 가중치 778MB + 프로그램 13MB, CPU 788MB.
이름에 모델 파일의 수정 시각이 들어가서, 모델을 새로 받으면 예전 캐시는 다시 쓰이지 않는다. 그래서 새로 받은 모델을 설치할 때도 예전 캐시를 지운다.
**출시(GPU)에서도 모델 2.6GB 외에 캐시 약 0.8GB가 더 든다.**

에뮬레이터 확인:

| 상황 | 결과 |
| --- | --- |
| 모델이 있을 때 끄기 → 취소 | 스위치가 다시 켜지고 모델 그대로 |
| 모델이 있을 때 끄기 → 지우기 | 모델과 캐시 3개(GPU 2개, CPU 1개, 합계 1.6GB) 삭제, 상태 "꺼짐 (주사위는 클라우드)", 메인 화면에 가도 받지 않음 |
| 다시 켜기 | 바로 받기 시작, 상태 "받는 중 0%" |
| 받는 중에 앱 업데이트(재설치) | 받기는 계속됨. 다음 실행 때 확인하고 설치하면서 예전 캐시를 지움 |

## 앱 크기와 리소스 분리

**정정**: 앞서 "Play는 200MB를 넘으면 받지 않는다"고 적었는데 틀렸다. 지금 Google Play 한도는 AAB 기준 기본 모듈 500MB, 설치 시 모듈·에셋 팩 합계 4GB다.
200MB를 넘으면 모바일 데이터 사용자에게 설치할 때 크기 안내 창이 뜰 뿐 막히지는 않는다. APK로 올리면 100MB 한도지만 새 앱은 AAB로 올려야 한다
([Play 크기 한도](https://support.google.com/googleplay/android-developer/answer/9859372)).

이미지 현황 (`res` 202MB):

| 묶음 | 개수 | 크기 | 쓰는 곳 |
| --- | --- | --- | --- |
| 아이템 (`item_img_*`) | 49 | 79.2MB | 코드에서 이름으로 (`getIdentifier`) |
| 몬스터 (`mon_*`) | 38 | 83.7MB | 코드에서 이름으로 (1장은 레이아웃에서도) |
| 이벤트 배경 등 | 12 | 32.6MB | 코드에서 이름으로 (`game_background` 8.8MB는 앱 아이콘) |
| 직업, 마법, UI | 35 | 6.7MB | 코드와 레이아웃 |

전부 알파 없는 1254×1254, 1536×1024 PNG라 손실 압축이 잘 먹는다. 300KB가 넘는 98장을 JPEG 품질 85로 바꿔 보면 **199.5MB → 24.5MB** (88% 감소). WebP는 보통 같은 품질에서 JPEG보다 더 작다.

| 방법 | 사용자가 받는 크기 | 할 일 |
| --- | --- | --- |
| WebP로 바꾸기 | 약 234MB → 60MB 안팎 | 이미지 파일만 바꿈. 코드 변경 없음 |
| install-time 에셋 팩으로 분리 | 그대로 (설치할 때 같이 받음) | 이름으로 불러오는 10여 곳을 한 함수로 바꾸고, 출시는 AAB, 디버그 빌드는 팩 폴더를 직접 포함 |
| fast-follow 에셋 팩으로 분리 | 처음 설치는 작아지지만 이미지가 설치 직후 따로 받아짐 | 위에 더해, 이미지가 아직 없을 때 화면 처리 |

## 따로 볼 것

- **출시 APK가 234MB**다. 아래 "앱 크기와 리소스 분리" 참고
- **첫 추론이 느림**: 에뮬레이터를 켠 직후 첫 주사위가 3번 모두 8초를 넘겨(8.1~8.3초) 클라우드로 넘어갔다. 앱만 다시 켰을 때는 4.1초. 모델 파일을 디스크에서 처음 읽는 시간으로 보인다. 실기기(0-B)에서도 그러면 로드 직후 짧은 워밍업 추론을 넣는다
- **받기를 끄는 방법이 없다**: Wi-Fi에서 2.6GB를 알아서 받는다. 출시 전에 설정에 "AI 모델 받기" 켜고 끄기나 지우기 버튼을 둘지 정해야 한다
- **GPU가 안 되는 기기에도 받는다**: GPU 초기화 실패(`FAILED`)는 프로세스 동안만 기억하므로, 받은 뒤 GPU가 안 되는 기기에서는 2.6GB가 쓰이지 않고 남는다. 0-B에서 S24 Ultra GPU가 되는지 먼저 본다
- **GPU 전용 파일**: 같은 저장소에 `gemma-4-E2B-it-gpu.litertlm`(2.0GB)도 있다. 출시는 GPU만 쓰므로 0-B에서 이 파일이 같거나 빠르면 600MB 덜 받는다. 아직 측정하지 않음
- **Hugging Face 저장소가 지워지거나 비공개가 되면** 받기가 실패한다 (3번 실패하면 그만 받고, 주사위는 클라우드)
