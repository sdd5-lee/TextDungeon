# 3단계 진행 상황 (2026-10-29)

## 3-1. 의존성과 빌드: 완료

- 쓰지 않는 `com.google.ai.client.generativeai:0.9.0`, `guava:31.1-android` 제거 (코드에서 쓰는 곳 없음). 빌드, 단위 테스트 164개, 에뮬레이터에서 앱 실행과 주사위 확인
- gson 선언을 실제로 쓰는 2.14.0으로 맞춤. `GsonRegressionTest`(세이브 저장/불러오기, type 없는 예전 세이브 복구, AI 이벤트 JSON) 통과
- 출시 빌드만 `abiFilters 'arm64-v8a'`. 출시 APK에는 `lib/arm64-v8a`만, 디버그 APK에는 `arm64-v8a`와 `x86_64`
- **출시 빌드가 원래 실패하고 있었다**: PNG 확장자인데 실제로는 JPEG인 이미지 12개(`job_*` 9개, `item_img_35~37`)를 출시 빌드의 PNG 압축이 처리하지 못함. 확장자를 `.jpg`로 바꿨다 (리소스 이름은 같아서 코드 변경 없음)

## 3-2. 모델 배포: 사용자 결정 필요

0-A에서 Play Asset Delivery 대신 **첫 실행 때 다운로드**로 정했다 (모델 2.58GB가 에셋 팩 한도 1.5GB를 넘음). 만들기 전에 정할 것:

| 항목 | 선택지 |
| --- | --- |
| 올려 둘 곳 | Cloudflare R2(내보내기 요금 없음, 계정 필요) / Hugging Face 원본 주소를 그대로 받기(추가 비용 없음, 그쪽 사정으로 주소가 바뀔 수 있음) |
| 언제 받을지 | 게임은 바로 하게 두고 뒤에서 받기(추천, 받는 동안 클라우드) / 첫 실행에 받고 시작 |
| 모바일 데이터 | Wi-Fi에서만 받기(추천) / 물어보고 받기 |

`ModelLocator`의 1번 자리에 받은 위치를 넣으면 나머지(로드, 폴백)는 1단계 코드 그대로 쓴다.

## 3-3. 상태 표시: 아직

설정 화면에 "온디바이스 AI: 준비됨 / 받는 중 / 사용 불가" 한 줄. "받는 중"이 다운로드와 묶여 있어서 3-2와 같이 한다. 상태는 `AiManager.getOnDeviceState()`로 이미 읽을 수 있다. 디버그 로그(응답한 백엔드)는 1단계에서 넣었다.

## 따로 볼 것

- **출시 APK가 234MB**다. Google Play는 기본 다운로드가 200MB를 넘으면 받지 않는다. 대부분이 이미지(`res` 207MB, 1024×1024 PNG 여러 장이 장당 2~6MB)라서 WebP로 바꾸면 크게 줄어든다 (Android Studio의 Convert to WebP). 모델과는 상관없는 문제
- **첫 추론이 느림**: 에뮬레이터를 켠 직후 첫 주사위가 3번 모두 8초를 넘겨(8.1~8.3초) 클라우드로 넘어갔다. 앱만 다시 켰을 때는 4.1초. 모델 파일을 디스크에서 처음 읽는 시간으로 보인다. 실기기(0-B)에서도 그러면 로드 직후 짧은 워밍업 추론을 넣는다
