## 최종 프롬프트 방식 (`ChaosDice.buildPrompt`)

- 괄호 안내문 대신 채워진 예시 1개를 보여 줌
- 아이템 후보는 현재 층 ±5층 이벤트에 나오는 아이템 중 5개 (`DataControlTower.getItemsForFloor`, `ChaosDice.pickItems`)
- HP 변화는 `HP-12`, `HP+10`으로 받고 파서가 `데미지`, `회복`으로 바꿈. 모델이 "체력"을 HP로, "데미지"를 적에게 준 피해로 이해하기 때문에 `체력`, `데미지`, `회복`은 모델에게 보여 주지 않음
  - 그래서 주사위 보상으로 `체력` 스탯(최대 HP 능력치)은 나오지 않음
- 파서 검사 (`ChoiceLineParser`): 안내문을 베낀 선택지, 기존 선택지나 예시와 같은 선택지, 숫자뿐인 보상설명은 실패로 처리

## 1단계 전에 확인할 것

1. **파싱 실패는 지금 클라우드로 재시도하지 않음.** 검사는 `ChaosDice`에서 하고 `FallbackBackend`는 백엔드 오류만 넘김. 지금은 오류 표시 후 주사위 횟수를 돌려줌. 1-2에서 검사를 폴백 경로 안으로 옮기거나 재시도를 추가해야 함
2. **주사위용 키 `GEMINI_API_KEY`가 401 "API key not valid"로 거절됨** (`AQ.`로 시작하는 53자). 지금 게임의 주사위도 클라우드에서 실패하고 있을 가능성이 큼. 키 교체 필요
3. **클라우드가 느림.** 전체 타임아웃 초안 20초로는 20건 중 6건이 잘림. `GeminiBackend`에서 생각 수준을 낮추는 방안 검토
4. **CPU 캐시와 저장 공간.** 공간이 모자라면 네이티브 코드에서 abort(예외로 못 잡음). 로드 전 남은 공간 확인 필요. 첫 실행 다운로드라면 모델 2.6GB와 캐시까지 합쳐 확인
5. GPU 초기화 실패에 걸리는 시간은 0-B에서 실기기로 확인
6. 묘사와 수치가 어긋나는 응답은 2-2(코드가 실제 적용 수치로 요약)에서 해결
7. 프롬프트가 긴 이벤트에서 600자 목표를 약간 넘음 (최대 662자)

## 측정 환경과 재현 방법

- 에뮬레이터: 측정용 AVD `TextDungeon_LLM` (Android 36 x86_64, RAM 6GB, 저장 16GB). 기존 `Pixel_9_Pro_XL`은 저장 공간 6GB라 모델과 캐시가 들어가지 않음
- 모델 파일: `C:\Users\super\models\` (프로젝트 밖)
- 측정 Activity: `app/src/debug/java/com/textdungeon/ai/OnDeviceSpikeActivity.java` (디버그 빌드 전용)
  1. 앱을 설치하고 Activity를 한 번 실행해 앱이 `models` 폴더를 만들게 함 (`adb shell mkdir`로 만들면 앱이 읽지 못함)
  2. `adb push <모델> /sdcard/Android/data/com.example.textdungeon/files/models/`
  3. `adb shell am start -n com.example.textdungeon/com.textdungeon.ai.OnDeviceSpikeActivity --es backend cpu --ez cloud false --ei count 20`
  4. 결과는 `files/spike/spike_시각.md` (adb pull)
