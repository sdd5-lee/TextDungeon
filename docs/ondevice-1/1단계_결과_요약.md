# 1단계 결과 요약 (2026-10-29)

계획서 v3.1의 1단계(엔진 연결). 0-B(실기기)는 아직이라 확인은 에뮬레이터(`TextDungeon_LLM`, CPU)에서 했다.

## 만든 것

| 파일 | 내용 |
| --- | --- |
| `ai/backend/OnDeviceBackend` | 상태 5개(`NOT_LOADED` `LOADING` `READY` `UNAVAILABLE` `FAILED`), 전용 스레드 하나에서 로딩·추론·해제, 요청마다 `Conversation`을 새로 만들고 닫음, 출력 200토큰, 생각 모드 끔, `<think>` 제거, `cancel()`은 `cancelProcess()` |
| `ai/backend/ModelLocator` | 모델 찾기. 1번 자리(첫 실행 다운로드)는 3단계에서 채움, 2번은 개발용 `files/models/` |
| `ai/backend/FallbackBackend` | 온디바이스 타임아웃(넘으면 추론을 멈추고 클라우드), 바깥 콜백 한 번만(`OnceCallback`), 응답한 백엔드를 로그에 남김 |
| `ai/backend/ResponseValidator` | 응답 검사를 백엔드에 넘김. **온디바이스 응답이 파서 검사를 통과하지 못하면 클라우드로 다시 요청** (0-A 요약의 1단계 전 확인 1번) |
| `ai/ChaosDice` | 주사위 전체 타임아웃, 콜백 한 번만 (선택지가 두 번 붙지 않게) |
| `ai/AiTimeouts` | 온디바이스 8초, 주사위 전체 35초 |
| `ai/AiManager` | `AiManager(Context)`, `warmUpOnDevice()`, `releaseOnDevice()`, `getOnDeviceState()`, `TRIM_MEMORY_BACKGROUND` 이상에서 해제 |
| `DifficultyActivity` / `EventActivity` / `DataControlTower` | 난이도 선택(AI 없는 쉬움 포함)과 `EventActivity.onResume`에서 로드, `resetRun()`·"메인 화면으로"·"게임종료"에서 해제 |
| `AndroidManifest.xml` | `libOpenCL.so`, `libvndksupport.so`를 main으로 옮김 |
| 디버그 전용 | `OnDeviceFlagsActivity`(장치, 램 검사, 지연, 타임아웃 플래그), `OnDeviceSpikeActivity --ei dice N`(게임과 같은 경로로 주사위) |

## 계획서와 다르게 한 것

| 항목 | 계획서 | 한 것 | 이유 |
| --- | --- | --- | --- |
| 주사위 전체 타임아웃 | 초안 20초 | **35초** | 계획서 공식(온디바이스 8초 + 클라우드 느린 쪽 10% + 여유)에 0-A 측정값 23.4초를 넣은 값. 20초면 클라우드 응답 20건 중 6건이 잘림 |
| 추론 실패 | 언급 없음 | **추론이 한 번 실패하면 `FAILED`로 두고 엔진을 내림** (멈춘 경우는 제외) | 0.18.0에서는 에뮬레이터 GPU 초기화가 실패하지 않고 85초~4분 41초 뒤 "성공"한 다음, 추론마다 5~7초 만에 "Can not find OpenCL library"로 실패했다. 그대로 두면 주사위마다 5~7초를 버린다 |
| 파싱 실패 | 언급 없음 | 클라우드로 재시도 | 0-A 요약의 1단계 전 확인 1번 |
| 전체 타임아웃 뒤 | 언급 없음 | 클라우드로 넘기지 않음 | 주사위가 이미 오류로 끝났는데 클라우드 요청을 보내면 낭비 |
| 램 기준 | 초안 6GB | `totalMem` 6GiB 미만이면 안 씀 | "6GB" 폰은 이보다 작게 나오므로 사실상 8GB 이상. Gemma가 Qwen보다 커서 보수적으로 둠. 0-B로 조정 |
| 로드 전 저장 공간 | 언급 없음 | `cacheDir` 남은 공간 1GB 미만이면 안 씀 | CPU 캐시(약 800MB)를 쓰다 공간이 모자라면 네이티브 abort (0-A 요약 4번) |
| 디버그 장치 플래그 | GPU 실패 시 CPU 허용 | `gpu`(기본) / `auto`(GPU 다음 CPU) / `cpu` | 에뮬레이터는 GPU 시도에 몇 분이 걸려서 CPU만 쓰는 값도 둠 |
| 해제 경로 | resetRun, 메인 화면으로 | "게임종료"도 추가 | `finishAffinity()`는 프로세스를 끝내지 않음 |

## 완료 기준 확인 (에뮬레이터)

클라우드는 주사위 키가 401이라 모든 클라우드 시도가 실패한다. 그래서 "클라우드로 넘어감"은 로그(`FallbackBackend`)와 HTTP 401로 확인했다.

| 상황 | 결과 |
| --- | --- |
| 모델 준비된 기기에서 주사위 | 통과. 게임 화면 2층에서 온디바이스 4.8초, 선택지 추가. 측정 Activity로 3.2~4.2초, 로그 `응답한 백엔드: OnDevice(CPU)` |
| 모델 없음 | 통과. `UNAVAILABLE` "모델 파일 없음" → 바로 클라우드 |
| 모델 로딩 중에 주사위 | 통과. `LOADING`이면 바로 클라우드 (310ms, 기다리지 않음) |
| 온디바이스를 일부러 지연 | 통과. 지연 15초: 8초에 클라우드로. 타임아웃 1.5초: 실제 추론 중 `cancelProcess()`가 6~30ms 안에 멈춤("CANCELLED"), 늦은 응답으로 선택지가 붙지 않음, 다음 주사위는 온디바이스 3.8초로 정상 |
| 클라우드까지 멈춤 | 통과. 지연 60초 + 타임아웃 60초로 흉내: 35초에 "시간 초과" 오류, 주사위 횟수 반환, 클라우드 요청 안 보냄 |
| 생성 중·뒤 백그라운드 → 복귀 | 통과. `HIDDEN`은 유지, `BACKGROUND`에서 해제(PSS 532→244MB), `EventActivity`로 돌아오면 다시 로드(0.4초) |
| 판이 끝난 뒤, "메인 화면으로" | 통과. "메인 화면으로"에서 해제(PSS 250MB), 이어하기에서 다시 로드. 측정 Activity 해제: 1,691MB → 204MB (로드 전 69MB) |
| 램 기준 미달 | 통과. 램 검사를 켜면 에뮬레이터(5,929MB)는 `UNAVAILABLE` → 클라우드 |
| GPU 미지원 | 통과. 첫 주사위가 5.5초 만에 실패하고 `FAILED`, 다음부터 바로 클라우드 |
| 32비트 기기 | 확인 못 함 (기기 없음). 코드는 `SUPPORTED_64_BIT_ABIS`에 arm64-v8a가 없으면 로드하지 않음 |

단위 테스트: `FallbackBackendTest` 9개 추가 (준비 안 됨, 오류, 검사 불통과, 시간 초과와 늦은 응답, 바깥 취소, 한 번만 콜백). 전체 159개 통과.

## 남은 것

- **0-B (실기기)**: `docs/ondevice-0A/0B_실기기_측정.sh`가 0-A 측정 20건(GPU, CPU)과 게임 경로 주사위 3번(출시와 같은 설정)을 한 번에 돈다. 결과로 `AiTimeouts.ON_DEVICE_MS`, 램 기준을 다시 정한다
- GPU 초기화는 엔진 안에서 멈출 수 없다. 에뮬레이터처럼 몇 분 걸리는 폰이면 그동안 전용 스레드가 묶인다 (주사위는 클라우드로 동작). 0-B에서 실기기 초기화 시간을 본다
- 주사위용 클라우드 키(`GEMINI_API_KEY`)가 401이라 지금은 온디바이스를 못 쓰는 경우 주사위가 실패한다. 키 교체 필요
- 클라우드 응답이 느림 (중앙값 15.8초). 생각 수준을 낮추는 방안은 키를 바꾼 뒤 확인

## 디버그 플래그 사용법

```
adb shell am start -S -n com.example.textdungeon/com.textdungeon.ai.OnDeviceFlagsActivity --es backend cpu --ez skipram true
adb shell am start -n com.example.textdungeon/com.textdungeon.ai.OnDeviceSpikeActivity --ei dice 3 --ez wait true --ez release true
```

`--el delay 15000`(일부러 지연), `--el timeout 1500`(온디바이스 타임아웃), `--ez reset true`(기본값으로). 결과는 Logcat 태그 `SPIKE`, `FallbackBackend`, `OnDeviceBackend`.
